# 상품 목록 이어 보기

## 업무 요청

상품 목록을 이어 보는 중에 상품이 추가되어도 이미 본 상품이 불필요하게 반복되지
않도록 개선하려고 합니다. 고객이 탐색을 이어 가거나 다시 시작할 수 있어야 합니다.

## Pair 시작 질문

> 목록을 보는 중 상품이 추가돼도 이미 본 상품이 다시 나오는 문제를 줄이고 싶어.
> 현재 탐색 흐름을 같이 살펴보면서 어디부터 접근할지 이야기해 보자.
> 아직 구체적인 구현 방법은 정하지 않았어.

## 빠른 시작

루트에서 `MARKETLANE_DB=.data/catalog-pagination.sqlite npm run dev`를 실행합니다.
main의 기본 DB나 다른 과제와 DB를 공유하지 마세요.
브랜치 전환·초기화 전 서버를 중지합니다. 필요할 때만 초기화하세요:
`MARKETLANE_DB=.data/catalog-pagination.sqlite npm run db:reset -- --confirm`

## 수용 기준

1. 고객이 목록을 처음부터 탐색하고 다음 묶음으로 이어 갈 수 있으며, 결과가 없거나
   끝에 도달한 상태를 알 수 있습니다. 실제로 제공하지 않는 페이지 수를 표시하지 않습니다.
2. 데이터가 변하지 않을 때 모든 대상 상품을 누락·중복 없이 볼 수 있습니다.
   기존 정렬 의미와 같은 가격·이름의 순서, 언어·검색·분류·재고 조건을 유지합니다.
3. 이미 본 구간에 새 상품이 추가되어도 정렬 값이 그대로인 기존 상품이 다시 나오지
   않습니다. 새 상품이 언제 보이는지와 탐색을 다시 시작하는 방법을 설명합니다.
4. 검색·언어·분류·정렬·재고 조건을 바꾸면 이전 조건의 결과와 섞이지 않습니다.
   이전 요청이 늦게 끝나도 새 탐색을 덮어쓰지 않습니다.
5. 탐색 도중 기존 상품의 가격·이름·재고가 달라졌을 때 제공하는 결과와 한계를
   사용자에게 명확히 알립니다. 이어 갈 수 없는 경우에는 다시 시작할 수 있습니다.
6. 기존 상품 탐색 이용자가 설명 없이 깨진 응답이나 다른 의미의 결과를 받지 않습니다.
   호환 정책을 설명하고 변경되는 사용 흐름을 일관되게 안내합니다.

## 범위

목록 탐색만 개선합니다. 상품 생성 화면, 재고 예약, 가격 규칙 변경은 포함하지 않습니다.
목록을 나누는 방식, 요청·응답 구조, 탐색 상태의 표현과 보관 방식은 정하지 않습니다.
