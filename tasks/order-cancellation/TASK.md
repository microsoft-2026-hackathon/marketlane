# 발송 전 주문 취소

## 업무 요청

운영자가 잘못 접수한 주문을 발송 전에 취소하고 재고를 되돌리되 과거 기록은 남겨야 합니다.
Placed·packing 주문의 취소를 추가하세요. Shipped 주문은 이 작업의 범위 밖입니다.

## Pair 시작 질문

> 운영자가 잘못 접수한 주문을 취소하고 재고를 돌려놓을 수 있게 하고 싶어.
> 현재 주문 처리 흐름을 같이 살펴보면서 어디부터 접근할지 이야기해 보자.
> 아직 구체적인 구현 방법은 정하지 않았어.

## 빠른 시작

루트에서 `MARKETLANE_DB=.data/order-cancellation.sqlite npm run dev`를 실행합니다.
main의 기본 DB나 다른 과제와 DB를 공유하지 마세요.
브랜치 전환·초기화 전 서버를 중지합니다. 필요할 때만 초기화하세요:
`MARKETLANE_DB=.data/order-cancellation.sqlite npm run db:reset -- --confirm`

## 수용 기준

1. 접수·포장 중 주문은 사유를 입력해 취소할 수 있고 발송된 주문은 취소할 수 없습니다.
   취소된 주문은 포장·발송할 수 없으며 목록과 상세에서 취소 상태를 알아볼 수 있습니다.
2. 취소 사유와 시각을 확인할 수 있습니다. 원래 고객·상품·수량·가격·할인·배송비·메모와
   기존 처리 시각은 보존하며 주문을 삭제하거나 금액 0으로 바꿔 기록하지 않습니다.
3. 주문 수량만큼 재고가 정확히 한 번 돌아오고 취소에 따른 변동 이력을 확인할 수 있습니다.
   실패 시 주문만 취소되거나 재고만 복원되는 부분 반영이 없습니다.
4. 취소를 반복하거나 동시에 요청해도 재고와 이력이 중복 생성되지 않습니다. 재시작 후에도
   취소 결과를 유지하고, 이미 기록된 사유·시각을 다른 요청으로 조용히 덮어쓰지 않습니다.
5. 같은 주문의 발송과 취소가 겹치면 하나의 결과만 성립합니다. 발송된 주문의 재고가
   취소 처리로 되돌아오지 않으며, 실패한 쪽은 현재 상태와 이유를 확인할 수 있습니다.
6. 운영 요약의 접수 매출·분류별 수량과 매출에서 취소 주문을 제외합니다. 진행 중 주문에는
   접수·포장 주문만 남습니다. 기존 배송비 포함·제외 기준은 유지합니다.
7. 사용자는 취소 결과를 확인한 후 갱신된 재고·요약을 볼 수 있습니다. 실패를 완료처럼
   표시하지 않으며, 새 기능 도입 후에도 기존 주문 접수·포장·발송과 과거 조회가 동작합니다.

## 범위

발송 전 취소만 다룹니다. 환불, 반품, 실제 결제, 발송 후 되돌리기, 인증 변경은
포함하지 않습니다. 취소 요청 형식, 데이터 표현, 저장·경합 처리 방법은 정하지 않습니다.
