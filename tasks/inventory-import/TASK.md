# CSV 재고 조정 미리보기와 적용

## 업무 요청

운영자가 CSV로 받은 재고 정정·입고 내역을 확인한 뒤 한 번에 적용할 수 있게 하려 합니다.
잘못된 파일을 발견하고 적용 결과를 확인할 수 있어야 합니다.

## Pair 시작 질문

> 운영자가 여러 조정 내역을 파일로 받아 확인한 뒤 한 번에 적용할 수 있게 하고 싶어.
> 현재 재고 조정 흐름을 같이 살펴보면서 어디부터 접근할지 이야기해 보자.
> 아직 구체적인 구현 방법은 정하지 않았어.

## 빠른 시작

루트에서 `MARKETLANE_DB=.data/inventory-import.sqlite npm run dev`를 실행합니다.
main의 기본 DB나 다른 과제와 DB를 공유하지 마세요.
브랜치 전환·초기화 전 서버를 중지합니다. 필요할 때만 초기화하세요:
`MARKETLANE_DB=.data/inventory-import.sqlite npm run db:reset -- --confirm`

## 수용 기준

1. 상품 SKU, 조정 수량, 사유와 업무 reference를 담은 CSV를 선택하고 내용을 미리 볼 수
   있습니다. 인용된 쉼표·줄바꿈·따옴표도 올바르게 읽으며 지원 형식과 크기 한도를 안내합니다.
2. 잘못된 파일 형식, 미등록 상품, 잘못된 수량, 빠진 사유·reference와 중복 reference를
   위치와 함께 알립니다. 같은 상품의 여러 조정은 허용하지만 음수 재고를 만드는 결과는 허용하지 않습니다.
3. 미리보기에는 조정 내용과 오류, 상품별 현재·예상 수량이 나타납니다. 미리보기만으로
   재고나 이력이 바뀌지 않으며 오류가 있는 파일은 일부만 적용하지 않습니다.
4. 미리보기 이후 주문이나 수동 조정으로 재고가 달라져 더 이상 적용할 수 없다면
   전체 묶음을 거부하고 다시 검토할 수 있게 합니다. 실패한 일부 조정이 남지 않습니다.
5. 적용에 성공하면 모든 조정과 사유·reference를 이력에서 확인할 수 있습니다.
   응답 유실, 동시·반복 시도, 새로고침과 서버 재시작 후에도 같은 묶음이 중복 반영되지 않습니다.
6. 이미 적용한 묶음의 결과 확인과 실제 새 입고를 구분할 수 있습니다. 내용이 바뀐 파일을
   이전 묶음의 성공으로 오인하거나, 같은 내용의 새로운 입고를 영원히 막지 않습니다.
7. 기존 한 건씩 하는 수동 조정과 주문 차감의 의미·이력을 유지합니다.
   화면에서 파일 확인, 명시적 적용, 실패·불확실한 결과의 확인 흐름을 사용할 수 있습니다.

## 범위

로컬 CSV 업무만 다룹니다. 스프레드시트 편집기, 공급업체 연동, 주문 재시도 기능은
포함하지 않습니다. 파싱 도구, 묶음 식별법, 저장 구조, 적용·복구 방식은 정하지 않습니다.

## 업무 입력 예시

[sample-adjustments.csv](sample-adjustments.csv)는 입력 형식 예시이며 초기 재고를 가정하지 않습니다.
업무 입력 파일은 사용할 수 있지만 완료 기준이나 구현 지침을 대신하지 않습니다.
