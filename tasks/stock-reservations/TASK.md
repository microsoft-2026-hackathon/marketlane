# 장바구니 재고를 5분간 예약하기

## 업무 요청

고객이 구매를 결정하는 동안 장바구니 재고를 선택적으로 예약할 수 있게 하세요.
종료 시각을 표시하고 다른 구매자로부터 수량을 보호하되 예약 없는 일반 Checkout도 유지합니다.
예약은 가격이 아닌 수량을 보호하며 브라우저 초안과는 별개입니다.

## Pair 시작 질문

> 고객이 구매를 결정하는 동안 선택한 수량을 잠시 확보할 수 있게 하고 싶어.
> 현재 장바구니·주문 흐름을 같이 살펴보면서 어디부터 접근할지 이야기해 보자.
> 아직 구체적인 구현 방법은 정하지 않았어.

## 빠른 시작

루트에서 `MARKETLANE_DB=.data/stock-reservations.sqlite npm run dev`를 실행합니다.
main의 기본 DB나 다른 과제와 DB를 공유하지 마세요.
브랜치 전환·초기화 전 서버를 중지합니다. 필요할 때만 초기화하세요:
`MARKETLANE_DB=.data/stock-reservations.sqlite npm run db:reset -- --confirm`

## 수용 기준

1. 고객이 선택적으로 장바구니 수량을 예약하고 수정·해제·확인할 수 있습니다.
   고객별 복수 예약 허용 여부를 안내하며 다른 고객의 예약 수량을 사용할 수 없습니다.
2. 예약과 성공한 수정은 5분간 유효하고 종료 시각·남은 시간·만료 여부를 볼 수 있습니다.
   조회, 견적, 새로고침이나 실패한 수정만으로 유효 시간이 늘어나지 않습니다.
3. 예약은 실제 물리 재고를 입출고한 것처럼 바꾸지 않지만 다른 구매자가 사용할 수 있는
   수량은 줄어듭니다. 상품의 재고 표시·필터, 견적, 일반 주문과 수동 조정이 이를 반영합니다.
4. 예약 증가가 실패하면 기존 수량과 만료를 유지하고 감소·해제·만료 시 해당 수량을
   다시 사용할 수 있습니다. 여러 작업이 겹쳐도 같은 재고를 중복 확보하거나 음수로 만들지 않습니다.
5. 고객은 자신의 유효한 예약과 일치하는 수량으로 주문할 수 있습니다. 현재 가격이
   적용되며 주문 실패로 예약만 사라지거나 주문 성공 후 예약 수량이 계속 묶이지 않습니다.
6. 만료 시각부터는 해당 예약으로 주문할 수 없고 사용한 예약을 다시 사용할 수도 없습니다.
   만료·주문 처리가 겹쳐도 같은 수량을 두 고객에게 판매하지 않습니다.
7. 서버 재시작 후에도 유효한 예약과 원래 만료 시각이 유지됩니다. 이미 만료된 예약은
   재고를 계속 묶지 않으며 고객이 새로 요청하지 않은 예약을 되살리지 않습니다.
8. 화면에서 예약 수량과 일반 구매 가능 수량을 구분할 수 있습니다. 실패·만료를 성공처럼
   표시하거나 장바구니 초안을 잃지 않으며 기존 예약 없는 주문도 사용할 수 있습니다.

## 범위

수량만 예약합니다. 가격 고정, 자동 연장, 실제 결제, 인증 변경은 포함하지 않습니다.
예약 식별법, 저장 구조, 만료 감지나 동시 작업 처리 방법은 정하지 않습니다.
