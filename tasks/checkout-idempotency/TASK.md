# 접수 여부가 불확실한 Checkout을 안전하게 재시도하기

## 업무 요청

Checkout 응답을 잃은 고객은 새 구매가 아니라 이미 접수된 주문을 안전하게 복구해야 합니다.
같은 구매를 확인하려는 재시도와 실제로 새로 구매하려는 행동을 구분할 수 있어야 합니다.

## Pair 시작 질문

> 주문 응답을 못 받은 고객이 다시 눌렀을 때 같은 구매가 중복 접수되지 않게 하고 싶어.
> 현재 주문 흐름을 같이 살펴보면서 어디부터 접근할지 이야기해 보자.
> 아직 구체적인 구현 방법은 정하지 않았어.

## 빠른 시작

루트에서 `MARKETLANE_DB=.data/checkout-idempotency.sqlite npm run dev`를 실행합니다.
main의 기본 DB나 다른 과제와 DB를 공유하지 마세요.
브랜치 전환·초기화 전 서버를 중지합니다. 필요할 때만 초기화하세요:
`MARKETLANE_DB=.data/checkout-idempotency.sqlite npm run db:reset -- --confirm`

## 수용 기준

1. 같은 구매의 재시도가 반복되거나 동시에 도착해도 주문과 재고 차감이 한 번만 발생합니다.
   이미 접수된 구매라면 원래 주문을 확인할 수 있습니다.
2. 접수 후 성공 응답을 잃거나 브라우저를 새로고침하고 서버를 재시작해도 원래 구매의
   결과를 확인할 수 있습니다. 복구가 새 구매나 추가 재고 차감으로 바뀌지 않습니다.
3. 동일한 상품을 의도적으로 다시 구매할 수 있습니다. 다른 고객의 구매나 내용이 바뀐
   장바구니를 이전 구매의 재시도로 잘못 처리하지 않습니다.
4. 복구 시 원래 주문의 상품·수량·가격·할인·배송비가 유지됩니다. 이후 상품 정보나
   재고가 바뀌어도 원래 접수 결과를 바꾸거나 진행된 포장·발송을 되돌리지 않습니다.
5. 재고 부족이나 잘못된 입력으로 거부된 주문은 일부 상품의 차감이나 거짓 성공을
   남기지 않습니다. 고객은 실패 이유와 다음에 취할 행동을 알 수 있습니다.
6. 화면은 접수 성공, 실패, 아직 확인되지 않은 상태를 구분합니다. 접수 확인 전에
   장바구니를 잃지 않으며, 고객·장바구니를 바꿔도 이전 구매의 복구가 뒤섞이지 않습니다.
7. 기존 일반 주문과 과거 주문 조회를 유지하고, 새 기능 도입으로 기존 데이터가 사라지지 않습니다.

## 범위

주문 접수 여부 확인과 재시도만 다룹니다. 실제 결제, 인증, 예약, 취소 기능은 추가하지 않습니다.
같은 구매를 식별하는 방법, 요청 형식, 저장 위치와 복구 구조는 정하지 않습니다.
