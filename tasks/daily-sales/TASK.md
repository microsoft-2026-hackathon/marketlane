# 현지 날짜 기준 일별 주문 매출 보고

## 업무 요청

운영자가 날짜 범위와 지역 시간대를 선택해 일별 주문 매출을 볼 수 있게 하려 합니다.
표시된 금액을 실제 주문과 대조하고 매출이 없는 날짜도 알아볼 수 있어야 합니다.

## Pair 시작 질문

> 운영자가 날짜 범위를 골라 하루별 금액을 보고 원래 주문과 대조할 수 있게 하고 싶어.
> 현재 집계를 같이 살펴보면서 어디부터 접근할지 이야기해 보자.
> 아직 구체적인 구현 방법은 정하지 않았어.

## 빠른 시작

루트에서 `MARKETLANE_DB=.data/daily-sales.sqlite npm run dev`를 실행합니다.
main의 기본 DB나 다른 과제와 DB를 공유하지 마세요.
브랜치 전환·초기화 전 서버를 중지합니다. 필요할 때만 초기화하세요:
`MARKETLANE_DB=.data/daily-sales.sqlite npm run db:reset -- --confirm`

## 수용 기준

1. 운영자가 지역 시간대와 날짜 범위를 선택하면 그 지역의 주문 접수 날짜로 집계됩니다.
   선택한 시간대와 날짜의 포함 규칙이 화면에서 명확하며 장치 설정에 따라 결과가 바뀌지 않습니다.
2. 선택한 범위의 날짜가 순서대로 나타나고 주문 없는 날은 0으로 표시됩니다.
   날짜 경계, 윤일, 일광 절약 시간 전환에도 주문을 잘못된 날짜에 넣거나 중복 집계하지 않습니다.
3. 접수·포장·발송 주문을 모두 접수 매출에 포함합니다. 포장·발송 시각이나 이후 상품·고객
   수정이 과거 주문 금액과 분류, 보고 날짜를 바꾸지 않습니다.
4. 주문 수, 상품 소계, 할인, 할인 후 상품 금액, 배송비, 주문 합계와 분류별 수량·매출을
   구분합니다. 분류 매출은 배송비를 제외하며 기존 USD cents 금액 규칙을 유지합니다.
5. 여러 항목·분류가 섞인 주문도 주문 수와 배송비는 한 번만 집계합니다. 날짜별 합계,
   전체 기간 합계와 근거 주문의 금액이 정확히 일치해야 합니다.
6. 운영자가 일별 금액의 근거 주문을 모두 확인할 수 있습니다. 주문이 100건을 넘어도
   보고를 조용히 자르지 않으며 주문 없는 날짜도 확인할 수 있습니다.
7. 1~366일 범위를 지원하고 잘못된 날짜·역순 범위·지원하지 않는 시간대는 명확히
   알립니다. 유효하지 않은 입력을 다른 날짜로 조용히 바꾸지 않습니다.

## 범위

운영용 접수 주문 매출이며 실제 결제 정산, 환불, 세금, 환율 변환은 포함하지 않습니다.
기존 전체 기간 운영 요약은 유지합니다. 집계 위치, 조회 구조, 시간대 처리 기술은 정하지 않습니다.

## 관찰자 참고 입력

[timestamp-cases.json](timestamp-cases.json)은 날짜 경계의 업무 예시이며 초기 DB 설명이 아닙니다.
처음부터 Pair·Driver에게 전달하지 않으며 실제로 확인한 상황을 기록할 때 참고합니다.
